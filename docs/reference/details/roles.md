# Роли

## Backend-роли

| Роль | Назначение |
|---|---|
| `USER` | Базовая роль авторизованного пользователя. Сама по себе не открывает рабочее пространство frontend. |
| `STUDENT` | Студенческие сценарии: учебный контент, тестирование и собственные результаты. |
| `TEACHER` | Преподавательские сценарии: контент, вопросы, тесты, нагрузка, результаты. |
| `ADMIN` | Администрирование пользователей и академической структуры, а также расширенный доступ к рабочим областям. |

## Рабочие роли frontend

Frontend считает workspace-ролями только:

```text
STUDENT
TEACHER
ADMIN
```

Для доступа к рабочим разделам одной роли недостаточно: frontend также ожидает корректно привязанный `personId`.

## Приоритет рабочего пространства

При наличии нескольких ролей default priority:

```text
ADMIN → TEACHER → STUDENT
```

Подписи интерфейса:

| Код | Подпись |
|---|---|
| `ADMIN` | Администратор |
| `TEACHER` | Преподаватель |
| `STUDENT` | Студент |

## Важно

Числовое поле `role` в membership **не является** этой системой ролей. См. [неоднозначности](./reference-caveats.md).
