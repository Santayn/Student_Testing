# Возможности администратора

## 1. Назначение административного рабочего пространства

Роль `ADMIN` отвечает за подготовку и сопровождение среды, в которой работают преподаватели и студенты. Администратор управляет пользователями, ролевой моделью, академической структурой, назначениями, учебной нагрузкой и системными операциями.

Условно административные функции можно разделить на несколько блоков:

```text
Администратор
├── пользователи и доступ
├── академическая структура
├── назначения и учебная нагрузка
├── сопровождение учебного контента
├── результаты
└── системные операции
```

## 2. Управление пользователями

Раздел пользователей позволяет администратору находить и фильтровать учётные записи по основным данным и состоянию.

Для конкретного пользователя администратор может выполнять настройку учётной записи, персонального профиля и ролей.

### 2.1. Состояние учётной записи

Администратор может управлять активностью аккаунта, включая отключение и повторную активацию пользователя.

### 2.2. Персональный профиль

Учётная запись может быть связана с существующим персональным профилем или с новым профилем, созданным администратором. Персональные данные используются далее в учебных связях и отображении пользователей.

### 2.3. Назначение ролей

Пользователю можно назначить одну или несколько рабочих ролей. Многоролевой пользователь затем сможет переключаться между соответствующими рабочими пространствами.

## 3. Роли и права

В отдельном административном разделе поддерживается ролевая модель системы.

Администратор может:

- создавать роли;
- создавать права/permissions;
- настраивать набор прав для роли.

Раздел используется для централизованного управления логическими разрешениями приложения. При этом текущий интерфейс в большей степени ориентирован на создание и настройку, чем на полный CRUD всех элементов ролевой модели.

## 4. Факультеты

Администратор ведёт справочник факультетов. Для него предусмотрены стандартные операции просмотра, поиска, сортировки, создания, изменения и удаления.

Факультет участвует в дальнейшей организации групп и предметной структуры.

## 5. Учебные группы

Группы создаются в академическом контексте и могут связываться с факультетом.

Администратор может:

- просматривать группы;
- создавать и изменять их;
- удалять группы;
- открывать состав группы;
- добавлять студентов;
- исключать студентов из текущего состава;
- возвращать ранее исключённого студента.

Состав группы является важной частью последующего формирования учебной нагрузки и доступности контента для студентов.

## 6. Справочник предметов

Администратор ведёт общий справочник предметов. Поддерживаются создание, изменение, удаление, поиск и сортировка.

Сам факт существования предмета ещё не определяет, где он преподаётся и кто за него отвечает. Для этого предусмотрены отдельные связи.

## 7. Предметы факультетов

Отдельный раздел связывает предметы с факультетами. После выбора факультета администратор видит уже назначенные и доступные для назначения предметы.

Это позволяет отделить общий справочник предметов от структуры конкретного факультета.

## 8. Преподаватели и предметы

Администратор связывает преподавателей с предметами. В интерфейсе можно выбрать преподавателя, просмотреть назначенные и доступные предметы, добавить новое назначение или прекратить существующее.

Такая связь формирует предметную область преподавателя, но сама по себе ещё не заменяет учебную нагрузку на конкретную группу и период.

## 9. Учебная нагрузка

Учебная нагрузка объединяет ключевые объекты учебного процесса. При создании назначения используются, в частности:

- предмет;
- преподаватель;
- группа или несколько групп;
- тип нагрузки;
- учебный период;
- количество часов;
- версия курса при необходимости;
- состояние;
- примечание.

Администратор может создавать и изменять назначения. При работе с несколькими группами интерфейс формирует отдельные назначения для каждой выбранной группы.

Система также контролирует потенциальные дубли учебных назначений в одинаковом учебном контексте.

## 10. Типы нагрузки

Типы нагрузки используются как отдельный справочник для классификации учебной работы. Примерами могут быть лекционные, практические или лабораторные занятия.

Текущий интерфейс позволяет создавать и редактировать типы нагрузки и использовать их при формировании назначений.

## 11. Работа с результатами

Администратор имеет доступ к расширенному режиму результатов и может анализировать данные в широком учебном контексте.

Фильтрация строится по цепочке предметов, лекций, тестов, групп и студентов. Это позволяет использовать результаты не только как личную информацию обучающегося, но и как административный источник контроля учебного процесса.

## 12. Сопровождение учебного контента

Текущая ролевая конфигурация предоставляет `ADMIN` доступ к преподавательским маршрутам учебного контента:

- темам;
- вопросам;
- созданию тестов;
- управлению лекциями;
- шаблонам курса.

Это предназначено для сопровождения системы и позволяет администратору помогать в поддержании данных. При этом некоторые действия намеренно остаются ориентированными на преподавателя. В частности, создание нового шаблона курса не рассматривается как обычная административная операция.

## 13. Резервные копии

Администратору доступен отдельный системный раздел резервного копирования.

Поддерживаются два основных действия:

1. создание и скачивание резервной копии базы данных;
2. восстановление базы из выбранного файла резервной копии.

Восстановление относится к потенциально опасным операциям, поскольку изменяет состояние данных системы. Поэтому оно требует отдельного подтверждения и должно выполняться осознанно.

## 14. Роль администратора в полном учебном цикле

Администратор фактически создаёт условия, необходимые для работы остальных ролей:

```text
Пользователь
  → персональный профиль
  → роль
  → факультет / группа / предмет
  → преподавательское назначение
  → учебная нагрузка
  → учебный контекст преподавателя и студентов
```

Без корректной настройки этих связей отдельные преподавательские и студенческие функции могут быть недоступны даже при наличии соответствующей роли.
