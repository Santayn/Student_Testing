# Возможности преподавателя

## 1. Назначение преподавательского рабочего пространства

Роль `TEACHER` предназначена для подготовки учебного контента и сопровождения обучения. Преподаватель работает в контексте доступных ему предметов, формирует темы и банк вопросов, создаёт тесты и лекции, управляет материалами и анализирует результаты студентов.

Общая логика работы может быть представлена следующим образом:

```text
Назначенные предметы
   ├── темы
   │    └── вопросы
   │          └── тесты
   ├── лекции
   │    ├── материалы
   │    └── связанные тесты
   ├── шаблоны и версии курса
   └── результаты студентов
```

## 2. Мои предметы

Преподаватель видит предметы, доступные ему в системе. Этот набор формируется не самой ролью `TEACHER`, а административными назначениями.

Предметный контекст используется в большинстве последующих операций: создании тем, вопросов, тестов, лекций и просмотре результатов.

## 3. Темы предмета

Для выбранного предмета преподаватель может вести тематическую структуру.

Поддерживаются:

- просмотр списка тем;
- поиск и сортировка;
- создание темы;
- изменение темы;
- удаление темы.

Тема включает порядковое положение, название и описание. Тематическая структура используется далее при организации банка вопросов и тестов.

## 4. Банк вопросов

Банк вопросов является самостоятельным рабочим разделом. Вопросы создаются в контексте предмета и темы.

Для списка предусмотрены поиск, фильтрация и сортировка. Преподаватель может создавать и изменять задания разных типов, а также управлять их активностью.

### 4.1. Общие параметры вопроса

Вопрос содержит основные свойства, среди которых:

- текст задания;
- тип вопроса;
- количество баллов;
- порядковое положение;
- признак активности.

### 4.2. Один правильный ответ

Для вопроса создаётся набор вариантов, один из которых отмечается как правильный.

### 4.3. Несколько правильных ответов

Для вопроса создаётся набор вариантов, среди которых может быть несколько правильных.

### 4.4. Сопоставление

Преподаватель задаёт пары соответствия, используемые студентом при прохождении задания.

### 4.5. Текстовый ответ

Для задания определяется текстовый правильный ответ, используемый системой при проверке.

### 4.6. Скрытие вопросов

Текущая пользовательская модель ориентирована не на безусловное физическое удаление вопроса, а на изменение его активности. Вопрос можно сделать скрытым/неактивным и при необходимости вернуть в активное состояние.

## 5. Импорт вопросов

Интерфейс предусматривает импорт вопросов из документа `.docx`. Преподаватель выбирает контекст темы и файл для импорта, после чего система создаёт распознанные вопросы и связанные варианты ответов в соответствии с поддерживаемым форматом.

Импорт дополняет ручной ввод и позволяет быстрее подготовить крупный банк заданий.

## 6. Создание теста

Создание теста организовано как последовательный многошаговый процесс.

### 6.1. Выбор учебного контекста

Определяются предмет, тема и учебные группы. Группы должны быть связаны с реальной учебной нагрузкой/назначениями преподавателя.

### 6.2. Основные параметры

Задаются название и описание теста.

### 6.3. Формирование состава вопросов

Преподаватель указывает общее количество вопросов и распределение по поддерживаемым типам. Также задаётся разрешённое количество попыток.

Система проверяет, достаточно ли активных вопросов выбранных типов для формирования теста. Если фиксированное количество вопросов по типам меньше общего числа, оставшаяся часть может быть добрана автоматически согласно логике редактора.

### 6.4. Доступность

Для теста задаются состояние и период доступности. Интерфейс предусматривает несколько состояний жизненного цикла, включая черновой, активный, закрытый и приостановленный варианты.

### 6.5. Назначение группам

После создания тест связывается с выбранными учебными назначениями групп. Таким образом тест не существует для студента как глобально доступный объект: возможность прохождения возникает через учебное назначение.

## 7. Управление лекциями

Преподаватель может создавать и сопровождать лекции в рамках выбранного предмета.

Доступны:

- создание лекции;
- редактирование;
- удаление;
- поиск;
- сортировка/фильтрация;
- управление публикацией;
- связывание с тестами;
- работа с материалами.

## 8. Материалы лекции

К лекции можно прикреплять файлы. Преподаватель может добавлять материалы, скачивать уже сохранённые файлы и удалять ненужные вложения.

Материалы становятся частью учебного содержимого, которое студент получает на странице лекции.

## 9. Связь лекции и тестов

Редактор лекции позволяет связывать лекцию с тестами. За счёт этого студент получает тестирование в логичном учебном контексте конкретного материала, а не через изолированный список тестов.

## 10. Шаблоны курса

Отдельная область предназначена для работы с шаблонами курса и их версиями.

Шаблон объединяет версии учебного курса и позволяет развивать содержимое без потери структуры предыдущих состояний.

Преподавателю доступны операции создания и изменения шаблонов, управление их видимостью и переход к версиям.

## 11. Версии курса

Для шаблона могут создаваться версии. Версия содержит номер, название, описание и сведения об изменениях. Она может находиться в опубликованном или неопубликованном состоянии.

Через версию курса осуществляется дальнейший переход к соответствующим лекциям.

## 12. Моя нагрузка

Раздел учебной нагрузки в преподавательском режиме преимущественно информационный. Он показывает сформированные администратором назначения преподавателя, например:

- предмет;
- группу;
- тип нагрузки;
- количество часов;
- учебный период;
- состояние назначения;
- примечания.

Преподаватель не формирует себе нагрузку самостоятельно. Этот процесс относится к административной роли.

## 13. Анализ результатов

Раздел результатов преподавателя позволяет последовательно сузить учебный контекст от предмета до конкретного обучающегося.

Типовая структура фильтрации:

```text
Предмет
  → лекция
  → тест
  → группа
  → студент
  → попытки и результаты
```

Преподаватель может анализировать показатели прохождения в пределах доступного ему учебного контекста.

## 14. Особенности текущей реализации

В текущем интерфейсе хорошо выделен отдельный сценарий **создания теста**, однако самостоятельный полноценный раздел управления всеми ранее созданными тестами как обычным CRUD-справочником выражен слабее. Существующие тесты далее используются через учебный контекст, в частности через лекции.

Для вопросов основной пользовательский механизм удаления из рабочего набора — изменение активности. Для версий курса также не все CRUD-операции представлены отдельными пользовательскими действиями.

Эти особенности не препятствуют основным учебным сценариям, но важны при описании границ текущей версии системы.
