# Возможности студента

## 1. Назначение студенческого рабочего пространства

Рабочее пространство `STUDENT` предназначено для прохождения учебного маршрута: от выбора доступного предмета и изучения лекционных материалов до прохождения назначенного теста и просмотра результата.

Типовой путь студента выглядит следующим образом:

```text
Предметы
  → предмет
  → лекции
  → конкретная лекция
  → материалы и назначенные тесты
  → попытка прохождения
  → результат
```

## 2. Работа с предметами

Студент получает список доступных ему предметов. Интерфейс предусматривает просмотр предметов, поиск и переход к информации по конкретному предмету.

Предмет является начальной точкой учебного сценария: через него студент переходит к лекциям и связанному учебному содержимому.

## 3. Просмотр лекций

Для выбранного предмета студент может открыть список доступных лекций. Лекция представляется как учебная единица, содержащая описательную информацию, материалы и связанные тесты.

В зависимости от подготовленного преподавателем содержимого студент может видеть:

- название лекции;
- описание;
- сведения о курсе/версии курса;
- прикреплённые материалы;
- доступные тесты.

## 4. Учебные материалы

Если к лекции прикреплены файлы, студент может скачивать их через интерфейс приложения. Материалы являются частью конкретной лекции и доступны в её учебном контексте.

Текущая реализация ориентирована прежде всего на описание лекции и файловые материалы. Полноценный отдельный редактор или отображение сложного семантического содержимого лекции не является основной возможностью текущей версии.

## 5. Доступность тестов

Тесты открываются студенту в контексте лекции и назначения. Интерфейс учитывает состояние доступности тестирования, в том числе наличие активной или продолжаемой попытки и количество оставшихся попыток.

Пользователь может столкнуться со следующими состояниями:

- тест доступен для новой попытки;
- имеется незавершённая попытка, которую можно продолжить;
- разрешённые попытки закончились;
- тест недоступен по своему текущему состоянию или периоду;
- отсутствует корректное назначение;
- состояние доступности временно не удалось определить.

Количество попыток контролируется не только визуальным состоянием интерфейса: запуск выполняется через серверный сценарий назначения теста.

## 6. Начало и продолжение попытки

Новая попытка запускается из учебного контекста, связанного с назначением. Если активная попытка уже существует, пользователь может продолжить её вместо создания новой.

Это предотвращает появление независимых попыток только из-за повторного открытия страницы.

Переход непосредственно по адресу теста без корректного контекста назначения не является нормальным пользовательским сценарием. Интерфейс ориентирует студента открывать тест со страницы соответствующей лекции.

## 7. Поддерживаемые типы вопросов

Во время тестирования студент может работать с четырьмя типами заданий.

### 7.1. Один вариант ответа

Из нескольких предложенных вариантов выбирается один ответ.

### 7.2. Несколько вариантов ответа

Пользователь может отметить несколько вариантов ответа.

### 7.3. Установление соответствия

Необходимо сформировать соответствия между предложенными элементами.

### 7.4. Текстовый ответ

Студент вводит ответ в текстовой форме.

## 8. Контроль прогресса

Во время прохождения теста интерфейс показывает общий прогресс: количество вопросов, на которые уже дан ответ, и число незаполненных вопросов.

Для отдельных вопросов также визуально различается состояние наличия или отсутствия ответа. Это позволяет студенту перед завершением теста оценить полноту заполнения.

## 9. Локальный черновик попытки

Ответы текущей попытки сохраняются локально в браузере. Это позволяет восстановить введённые данные после случайного перехода на другую страницу или повторного открытия теста в рамках той же попытки.

Черновик привязан не просто к идентификатору теста, а к контексту конкретной попытки и составу вопросов. За счёт этого данные одной попытки не должны автоматически переноситься в другую.

Локальный черновик не заменяет серверную фиксацию завершённого результата. Он предназначен только для сохранения промежуточных ответов до отправки попытки.

## 10. Завершение теста

Если студент пытается завершить тест с вопросами без ответа, интерфейс дополнительно предупреждает об этом и позволяет либо вернуться к заполнению, либо сознательно отправить попытку в текущем виде.

После успешной отправки отображается информация о результате, включая полученные показатели и доступные сведения об ответах.

В интерфейсе предусмотрена защита от неконтролируемой повторной отправки в ситуации, когда запрос завершения мог быть принят сервером, но клиент не получил достоверного ответа из-за сетевого сбоя.

## 11. Просмотр результатов

Раздел результатов в студенческом режиме предназначен только для собственных результатов текущего пользователя.

Студент может просматривать связанные с ним попытки и показатели, а также использовать доступные фильтры по учебному контексту. Интерфейс не рассчитан на просмотр результатов других студентов из режима `STUDENT`.

## 12. Границы возможностей студента

Студент не управляет:

- темами и вопросами;
- созданием тестов;
- лекциями и материалами как автор;
- предметами и группами;
- учебной нагрузкой;
- пользователями и ролями.

Такие операции относятся к преподавательскому или административному рабочему пространству.
