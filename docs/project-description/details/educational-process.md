# Организация учебного процесса

## 1. Общая идея

Student Testing строит учебный процесс не вокруг отдельных несвязанных экранов, а вокруг последовательности связанных сущностей. Академическая структура, преподавательские назначения, учебный контент, тестирование и результаты образуют единый цикл.

## 2. Базовые сущности процесса

К ключевым объектам относятся:

- пользовательская учётная запись;
- персональный профиль;
- роль;
- факультет;
- группа;
- предмет;
- назначение преподавателя на предмет;
- учебная нагрузка;
- тема;
- вопрос;
- тест;
- лекция;
- материал;
- назначение теста;
- попытка прохождения;
- результат.

## 3. Формирование академической основы

Первый уровень создаётся администратором:

```text
Факультет
   ├── группы
   └── доступные предметы
```

Параллельно в системе существуют пользователи с персональными профилями и ролями.

Студенты включаются в состав учебных групп, а преподаватели связываются с предметами.

## 4. Формирование учебной нагрузки

После создания справочников администратор формирует конкретную учебную нагрузку.

Упрощённо её можно представить как связь:

```text
Преподаватель
    + Предмет
    + Группа
    + Учебный период
    + Тип нагрузки
    + дополнительные параметры
```

Именно этот уровень превращает общий справочник предметов в конкретный учебный процесс для определённых групп и преподавателей.

## 5. Подготовка контента преподавателем

Получив предметный контекст, преподаватель может формировать содержательную часть обучения.

### 5.1. Темы

Предмет структурируется на темы.

### 5.2. Банк вопросов

В рамках темы создаются вопросы разных типов. Вопросы становятся исходным материалом для формирования тестов.

### 5.3. Тесты

Тест создаётся на основе выбранного предмета, темы, параметров отбора вопросов и учебных групп. Для него определяются количество вопросов, попытки и доступность.

### 5.4. Лекции

Преподаватель создаёт лекции, добавляет описание и файлы, а также связывает лекцию с соответствующими тестами.

### 5.5. Шаблоны и версии курса

Для более структурированного управления учебным содержанием могут использоваться шаблоны и версии курса, которые позволяют группировать и развивать учебные материалы во времени.

## 6. Получение контента студентом

Студент работает уже не со справочниками, а с подготовленным для него учебным маршрутом:

```text
Доступный предмет
    ↓
Лекции предмета
    ↓
Конкретная лекция
    ├── описание
    ├── материалы
    └── назначенные тесты
```

Список доступного содержимого зависит от сформированного учебного контекста.

## 7. Назначение теста и попытки

Связь студента с тестом строится через назначение. Это позволяет учитывать:

- конкретный учебный контекст;
- период доступности;
- состояние теста;
- разрешённое количество попыток;
- наличие незавершённой попытки.

Студент либо начинает новую допустимую попытку, либо продолжает существующую.

## 8. Завершение и результат

После отправки ответов формируется результат попытки. Он связан с конкретным тестом и обучающимся.

Далее данные используются на разных уровнях:

```text
Студент
  → видит собственный результат

Преподаватель
  → анализирует результаты по своему учебному контексту

Администратор
  → может анализировать результаты в расширенном административном контексте
```

## 9. Полный цикл

Полный жизненный цикл учебного процесса можно представить следующим образом:

```text
1. Администратор создаёт академическую структуру
        ↓
2. Пользователи получают профили и роли
        ↓
3. Студенты включаются в группы
        ↓
4. Преподаватели связываются с предметами
        ↓
5. Формируется учебная нагрузка
        ↓
6. Преподаватель создаёт темы и вопросы
        ↓
7. Преподаватель создаёт тесты
        ↓
8. Преподаватель создаёт лекции и материалы
        ↓
9. Студент получает доступ к учебному содержимому
        ↓
10. Студент проходит назначенный тест
        ↓
11. Система фиксирует результат
        ↓
12. Студент, преподаватель и администратор используют результат
    в пределах своих полномочий
```

## 10. Почему связи важны

Большинство пользовательских возможностей зависит от предварительно сформированных связей. Например:

- роль преподавателя без назначенного предмета не создаёт полноценного предметного контекста;
- предмет без учебной нагрузки не определяет конкретную группу обучающихся;
- тест без назначения не становится автоматически доступным студенту;
- студенческая роль без корректного персонального/группового контекста не гарантирует наличие учебных материалов.

Именно поэтому административная подготовка данных является частью общего учебного процесса, а не отдельной вспомогательной функцией.
