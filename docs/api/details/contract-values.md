# Контрактные числовые значения

API исторически использует `int` для ряда enum-подобных полей. Их смысл зависит от конкретного домена.

## Тип вопроса `Question.type`

| Значение | Смысл |
|---:|---|
| `1` | один вариант ответа (`Single choice`) |
| `2` | несколько вариантов (`Multiple choice`) |
| `3` | сопоставление (`Matching`) |
| `4` | текстовый ответ (`Text`) |

## Membership status

| Значение | Смысл |
|---:|---|
| `1` | активно |
| `2` | приостановлено |
| `3` | удалено / завершено membership |

При статусе `3` backend заполняет `removedAtUtc`.

## TestAssignment status

Frontend использует:

| Значение | UI-смысл |
|---:|---|
| `1` | Черновик |
| `2` | Активно |
| `3` | Закрыто |
| `4` | Приостановлено |

## TeachingAssignment status

| Значение | UI-смысл |
|---:|---|
| `1` | Активно |
| `2` | Черновик |
| `3` | Закрыто |
| `4` | В паузе |

Важно: одинаковые числа в `TestAssignment.status` и `TeachingAssignment.status` имеют разный порядок `Активно/Черновик`.

## TestAttempt status

В текущем lifecycle сервиса:

| Значение | Смысл |
|---:|---|
| `1` | активная/незавершённая попытка |
| `2` | завершённая попытка |

## Membership role

`role` в Faculty/Group/Subject membership — **контекстное** поле, а не application role `STUDENT/TEACHER/ADMIN`. Текущий frontend использует `role = 1` как student role в GroupMembership и teacher role в SubjectMembership. Не следует переносить числовое значение из одного membership domain в другой без проверки.

## TestAssignment scope

| Значение | Target | Дополнительное поле |
|---:|---|---|
| `1` | глобальное назначение | все target ID должны быть `null`; создание разрешено только администратору |
| `2` | версия курса | требуется только `courseVersionId` |
| `3` | конкретная лекция | требуется только `courseLectureId` |
| `4` | учебное назначение / группа | требуется только `teachingAssignmentId` |

Backend валидирует, что для выбранного scope установлен ровно допустимый target и не переданы несовместимые ID.

## Почему это важно

Числовые enum-поля являются частью wire contract. Изменение их смысла без версии API будет breaking change. Предпочтительное будущее направление — явные enums либо централизованный справочник contract values.
