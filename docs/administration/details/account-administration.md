# Администрирование учётных записей

## Что доступно штатно

Через административный интерфейс/API можно:

- просматривать пользователей;
- создавать и редактировать `Person`;
- привязывать `Person` к `User`;
- активировать и деактивировать `User`;
- назначать роли;
- управлять permissions через API/role model.

## User и Person

```text
User
→ login/password/security

Person
→ ФИО/email/phone/academic identity
```

Учётная запись может существовать без привязанного `Person`; такой пользователь не получает полноценный рабочий контекст и может оказаться на `account-pending`.

## Текущий пробел: создание User

В административном API отсутствует штатный:

```text
POST /users
```

При этом публичная регистрация по умолчанию отключена:

```text
APP_PUBLIC_REGISTRATION_ENABLED=false
```

Поэтому в чистой эксплуатационной среде отсутствует полноценный workflow:

```text
ADMIN → создать User → выдать временный пароль → назначить профиль/роль
```

Локальный DataLoader скрывает эту проблему, создавая демонстрационные аккаунты.

## Текущий пробел: password reset

Есть только смена пароля с подтверждением текущего пароля. Нет:

- admin reset password;
- forgot-password;
- recovery token;
- temporary password flow.

Если пользователь потерял пароль, штатного operator workflow сейчас нет.

## Рекомендация

До production-эксплуатации желательно реализовать:

1. защищённое создание User администратором;
2. безопасный reset/recovery;
3. требование смены временного пароля при первом входе;
4. аудит таких административных действий.
