# Доступ администратора и восстановление доступа

## Локальная среда

При включённом DataLoader создаётся демонстрационный ADMIN. Эти данные предназначены только для локальной/demo среды и не должны использоваться как production bootstrap.

## Production bootstrap

При отключённом:

```text
APP_DATA_LOADER_ENABLED=false
```

проект сейчас не имеет отдельного CLI/скрипта для создания первого администратора.

Это означает, что чистое production-развёртывание требует заранее подготовленного bootstrap-механизма или ручной работы с данными.

## Риск last-admin lockout

Текущие сервисы позволяют:

- заменить роли пользователя пустым набором;
- деактивировать пользователя.

Явной защиты вида:

```text
нельзя отключить последнего ADMIN
нельзя снять ADMIN с последнего администратора
нельзя деактивировать самого себя без второго ADMIN
```

в текущем workflow нет.

Поэтому оператор должен соблюдать правило:

> Перед изменением ролей или активности администратора убедиться, что существует второй проверенный активный ADMIN.

## Минимальная безопасная процедура

Перед обслуживанием административных аккаунтов:

1. проверить наличие минимум двух активных ADMIN;
2. войти вторым ADMIN в отдельной сессии;
3. только после этого менять роль/активность первого;
4. повторно проверить вход;
5. не использовать DataLoader как recovery strategy.

## Целевое улучшение

Backend должен гарантировать invariant:

```text
active ADMIN count >= 1
```

для операций деактивации и замены ролей.
