# Резервное копирование файлов лекций

## Где находятся файлы

В Docker файлы лекций хранятся в named volume:

```text
lecture-uploads
→ /app/uploads/lecture-materials
```

PostgreSQL содержит только метаданные и `storedPath`.

## Что нужно резервировать

Для сохранения материалов необходимо копировать **сам volume**, а не только БД.

Один из общих Docker-подходов — временный контейнер, который архивирует volume в каталог host. Конкретная команда зависит от ОС и политики хранения. Главное правило:

```text
source = Docker volume lecture-uploads
result = внешний архив/backup вне исходного volume
```

## Согласованность с БД

DB и file backup должны быть сделаны максимально близко по времени или в maintenance window.

Иначе возможны состояния:

```text
DB содержит LectureMaterial, а файла нет
```

или:

```text
файл существует, но DB record отсутствует
```

## Restore файлов

При восстановлении файлового volume нужно использовать backup, соответствующий тому же логическому snapshot, что и SQL dump.

## Orphan files

При неудачной транзакции upload физический файл теоретически может остаться после rollback DB record. Автоматического orphan cleanup job сейчас нет.

Периодическое обслуживание файлового хранилища пока требует ручной осторожной проверки и не должно удалять файлы только по имени без сверки с БД.
