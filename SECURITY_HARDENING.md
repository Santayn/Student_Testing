# Усиление безопасности Student Test

Ветка: `security/hardening`.

## Что исправлено

- административные изменения ролей, пользователей, факультетов, групп,
  предметов и членств закрыты правами администратора;
- API тем, вопросов, лекций, курсов и тестов проверяет не только роль, но и
  владельца конкретного объекта;
- для тестов добавлен защищённый `DELETE /api/v1/tests/{id}`; связанные данные
  по-прежнему защищены ограничениями целостности БД;
- администратор с дополнительной ролью преподавателя сохраняет полный доступ;
- студент получает только свои членства, назначения, попытки и результаты;
- преподаватель получает результаты только своих предметов, групп и студентов;
- правильные ответы больше не возвращаются студенту после попытки и в истории
  результатов;
- `personId`, балл, признак правильности, итоговый статус и итоговый балл нельзя
  подменить в API прохождения теста;
- набор вопросов фиксируется в момент создания попытки, ответы на посторонние
  вопросы отклоняются, итоговый балл вычисляется только сервером;
- лимит попыток считается по тесту и студенту, а не отдельно для каждого
  назначения одного теста;
- запуск попыток сериализован блокировкой строки теста; уникальные индексы
  дополнительно защищают номер попытки внутри назначения, активную попытку и
  единственный ответ на вопрос;
- доступность теста учитывает лимит попыток и возвращает `attemptsRemaining`;
- подписи статусов назначения теста во frontend согласованы с backend:
  `1 — черновик`, `2 — активно`;
- публичная регистрация с привязкой к произвольной персоне выключена по
  умолчанию (`APP_PUBLIC_REGISTRATION_ENABLED=false`);
- actor-поля создания/публикации курса и отметки прогресса берутся из JWT, а не
  из тела запроса;
- ошибки 401, 403, 404 и бизнес-ошибки возвращаются в одном формате
  `code/message/details/traceId`;
- CORS ограничен заданными origin, локальные `@CrossOrigin` удалены;
- JWT-секрет и пароль БД обязательны, слабый встроенный JWT-секрет удалён;
- production-настройки по умолчанию используют `ddl-auto=validate`, не запускают
  `schema.sql` и не загружают демонстрационные данные;
- Docker backend работает не от root, получил healthcheck; PostgreSQL и backend
  привязаны к loopback-интерфейсу; Nginx получил защитные HTTP-заголовки.

## Локальный запуск

```bash
cp .env.example .env
```

В `.env` необходимо заменить минимум:

```dotenv
POSTGRES_PASSWORD=сложный-пароль-базы
APP_JWT_SECRET=случайная-строка-длиной-не-менее-32-символов
```

После этого:

```bash
docker compose up -d --build
```

Главная страница: `http://localhost/`.

Профиль `local` оставляет автоматическое создание схемы и демонстрационные
данные для разработки. Для развёртывания следует использовать существующую
мигрированную БД и значения:

```dotenv
SPRING_PROFILES_ACTIVE=prod
SPRING_JPA_HIBERNATE_DDL_AUTO=validate
SPRING_SQL_INIT_MODE=never
APP_DATA_LOADER_ENABLED=false
APP_PUBLIC_REGISTRATION_ENABLED=false
```
