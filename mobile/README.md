# Student Testing — мобильное приложение

Нативный клиент для Android и iOS на **Kotlin Multiplatform + Compose Multiplatform**.
Повторяет функциональность веб-фронтенда (`../frontend`) для всех ролей — студента, преподавателя и администратора —
и работает с тем же REST API бэкенда (`/api/v1`).

| | |
|---|---|
| Язык | Kotlin 2.4 |
| UI | Compose Multiplatform 1.12, Material 3 (цвета и шрифт Manrope из `frontend/src/theme`) |
| Сеть | Ktor 3 (OkHttp на Android, Darwin на iOS), kotlinx.serialization |
| DI | Koin 4 |
| Навигация | Navigation Compose (type-safe routes) |
| Файлы | FileKit (выбор, сохранение и открытие файлов) |
| Хранилище | SharedPreferences / NSUserDefaults; токены — Android Keystore + Tink / iOS Keychain |
| Сборка | Gradle 9.6, AGP 9.4, Android compileSdk 37, minSdk 26, iOS 15.3+ |

## Структура

```
mobile/
  shared/        — весь общий код: логика, API, UI (commonMain) + платформенные части (androidMain, iosMain)
  androidApp/    — Android-приложение (Activity, манифест, иконка)
  iosApp/        — Xcode-проект-обёртка (SwiftUI → Compose)
```

Внутри `shared/src/commonMain/kotlin/org/santayn/testing/mobile`:

| Пакет | Что внутри | Аналог во фронте |
|---|---|---|
| `core/network` | `ApiClient`: Bearer-токен, проактивный refresh, один повтор после 401, отбрасывание ответов старой сессии, повторы и офлайн-кеш GET; `NetworkStatus` (сеть устройства + доступность сервера); `ApiException` | `api/http.js`, `api/error.js` |
| `core/session` | `SessionManager` (вход, single-flight refresh, выход, смена пароля), рабочие роли | `stores/auth.js`, `utils/workspaceRole.js` |
| `core/storage` | настройки (тема, размер текста, контраст, адрес сервера, роль), защищённое хранилище, `ResponseCache` (офлайн-кеш) | `stores/theme.js` |
| `core/files` | загрузка/скачивание файлов, `OfflineFiles` — материалы лекций для просмотра без сети | — |
| `core/platform` | платформенные части: адрес по умолчанию, `TextSpeaker` (чтение вслух) | — |
| `core/ui` | тема, общие компоненты (поля, выбор, диалоги, состояния загрузки) | `components/ui` |
| `data/api`, `data/model` | API-классы и DTO, один к одному с `frontend/src/api/*.api.js` | `api/*` |
| `domain` | контекст студента и преподавателя, черновики попыток, сопоставление, подсчёт баллов | `utils/*` |
| `navigation` | маршруты, нижняя панель по ролям, меню | `router`, `navigation` |
| `feature/*` | экраны: `auth`, `home`, `profile`, `learning`, `tests`, `results`, `teacher/*`, `admin/*` | `views/*` |

Каждый экран — это `@Composable` плюс `ViewModel` со `StateFlow`. Новую функцию проще всего добавлять так:
API-метод в `data/api` → ViewModel и экран в `feature/...` → регистрация в `di/ViewModels.kt` → маршрут в `navigation`.

## Запуск

### 1. Бэкенд
Из корня репозитория (см. корневой README):
```
docker compose up -d
```

### 2. Android (Windows / macOS / Linux)
Понадобятся Android Studio (с JDK 21) и Android SDK Platform 37.

- **Android Studio:** откройте папку `mobile/`, выберите конфигурацию `androidApp` и эмулятор, нажмите Run.
- **Терминал:**
  ```
  cd mobile
  ./gradlew :androidApp:installDebug
  ```

В эмуляторе сервер по умолчанию — `http://10.0.2.2:8080/api/v1` (это порт бэкенда на компьютере).

### 3. Телефон в той же Wi-Fi-сети
На экране входа нажмите иконку сервера справа вверху (или «Адрес сервера» в профиле) и укажите IP компьютера, например `192.168.31.179`.
Приложение пойдёт на `http://192.168.31.179/api/v1` через nginx фронтенда (порт 80);
порт 8080 бэкенда снаружи закрыт (Docker публикует его только на 127.0.0.1) — это нормально.
Если запросы не проходят, разрешите входящие подключения на порт 80 в брандмауэре Windows.
Установка на подключённый по USB телефон: `./gradlew :androidApp:installDebug` (ставит на все подключённые устройства).

### 4. iOS (нужен Mac с Xcode)
1. Откройте `iosApp/iosApp.xcodeproj` в Xcode.
2. Для запуска на iPhone укажите свой Team ID в `iosApp/Configuration/Config.xcconfig` (`TEAM_ID=`).
3. Нажмите Run. Gradle-фреймворк `Shared` соберётся сам на шаге «Compile Kotlin Framework».

Адрес сервера задаётся на экране входа (иконка сервера справа вверху): укажите IP компьютера, где запущен Docker.
В `Info.plist` для локальной разработки разрешён HTTP (ATS) — для production с HTTPS эти исключения нужно убрать.

## Работа без сети и при недоступном сервере
- **Состояние связи.** `NetworkStatus` отличает «нет интернета на устройстве» (Android `ConnectivityManager`, iOS `NWPathMonitor`)
  от «сервер не отвечает» (сетевая ошибка, таймаут или 502–504 от nginx). Под заголовком каждого экрана появляется плашка
  «Нет подключения к интернету» / «Сервер недоступен» (с кнопкой «Проверить»), её зачитывает TalkBack/VoiceOver.
- **Офлайн-кеш.** Два независимых хранилища:
  - *данные экранов* — каждый успешный GET-ответ (JSON, ключ — пользователь + URL), до 20 МБ и 30 дней.
    Это только текст: весь контекст студента или справочники админа занимают единицы–сотни КБ;
  - *материалы лекций* (PDF, презентации, видео — бэкенд принимает любые файлы до 50 МБ каждый):
    скачиваются потоком прямо в файл с прогрессом «скачивание 45 %», без загрузки в память,
    и открываются без сети. Лимит задаётся в профиле ползунком (логарифмическая шкала) или вводом с клавиатуры
    («500», «2 ГБ», «1,5 GB») — от 100 МБ до 10 ГБ, по умолчанию 200 МБ;
    при переполнении удаляются давно скачанные материалы. Там же видно занятое место и есть «Удалить сохранённые данные».

  Без связи экраны показывают сохранённые данные с отметкой «Показаны сохранённые данные от …».
  Всё это удаляется при выходе из аккаунта.
- **Запуск без сети.** Профиль пользователя сохраняется в защищённом хранилище: приложение открывается сразу,
  а сессия проверяется в фоне и повторно — когда связь вернётся (отозванные токены → выход).
- **Повторы.** Если сохранённых данных нет, GET при сетевой ошибке или 502–504 повторяется до двух раз.
- **Восстановление.** Пока сервер недоступен, он периодически проверяется (5 с → 60 с). Как только связь вернулась,
  открытый экран перезагружает данные сам. Тест в процессе прохождения не перезапускается — только повтор после ошибки.
- **Изменения** (POST/PUT/DELETE) без связи не ставятся в очередь: пользователь видит сообщение и повторяет действие.
- **Сбой загрузки части экрана** (например, состава группы) показывается как ошибка с кнопкой «Повторить», а не как пустой список.
- **VPN.** Сеть VPN не считается подключением: VPN-клиент остаётся «подключённым» и в авиарежиме.
  При смене сети пул соединений OkHttp сбрасывается — иначе первый запрос после восстановления связи висит до таймаута.

## Доступность
Ориентир — WCAG 2.1 AA / ГОСТ Р 52872-2019 (распространяется и на мобильные приложения).
- **Озвучивание всего интерфейса** — системные TalkBack (Android) и VoiceOver (iOS):
  - варианты ответа — один элемент с ролью «переключатель»/«флажок» и состоянием;
  - выпадающие списки называют поле и выбранное значение (в сопоставлении — «Соответствие для «…»»);
  - заголовки экранов, разделов и вопросов помечены как заголовки (переход жестом «по заголовкам»);
  - ошибки, предупреждения, плашка связи и «Тест завершён» объявляются автоматически (live region);
  - кнопки-иконки подписаны, у нижней панели названия вкладок есть и при скрытых подписях.
- **«Прочитать вслух»** в вопросах теста и описании лекции — встроенный синтез речи (Android TextToSpeech, iOS AVSpeechSynthesizer, голос ru-RU),
  для тех, кто плохо видит, но не пользуется программой чтения с экрана.
- **Специальные возможности** (профиль и кнопка ♿ на экране входа — аналог «версии для слабовидящих»):
  размер текста «Обычный / Крупный ×1.25 / Очень крупный ×1.5» поверх системного шрифта, «Высокий контраст»
  (светлый и тёмный, текст не ниже 7:1), тема.
- **Контраст.** Палитра сайта проверяется тестом `ContrastTests` (≥ 4.5:1). Чтобы пройти AA, по сравнению с сайтом
  немного затемнён приглушённый текст светлой темы и осветлён primary тёмной темы (подробности — в `Theme.kt`).
- **Сенсорные цели** — не меньше 48 dp; статусы передаются текстом и значком, а не только цветом.
- Системные анимации отключаются настройкой Android «Удалить анимации» (Compose учитывает её сам).

## Тесты
### Юнит-тесты (JVM, без устройства)
```
./gradlew :shared:testAndroidHostTest
```
Покрыты (34 теста):
- логика сопоставления и сборки ответа на тест, сигнатура черновика;
- подсчёт баллов и лучшая попытка;
- рабочие роли, разбор `Content-Disposition`;
- сессия на mock-бэкенде: восстановление, single-flight refresh при параллельных запросах, повтор после 401, выход при отклонённом refresh;
- офлайн: ответ из кеша при недоступном сервере, «нет интернета» vs «сервер недоступен», повторы 502, мгновенный ответ из кеша
  при известном сбое, вытеснение старых записей, восстановление сессии без сети и её проверка после;
- `NetworkStatus`: событие восстановления сети, обнаружение ожившего сервера пробой;
- контраст всех четырёх палитр (AA и AAA для высокого контраста);
- имя файла с кириллицей уходит в multipart в UTF-8 (бэкенд читает его как UTF-8).

### UI-тесты доступности (на эмуляторе или телефоне по USB)
```
./gradlew :shared:connectedAndroidDeviceTest
```
`shared/src/androidDeviceTest/.../AccessibilityUiTests.kt`, 14 тестов. Используются Compose UI Test и
Google Accessibility Test Framework (те же проверки, что в Accessibility Scanner: размер сенсорных целей,
контраст текста, подписи элементов) — ошибка ATF валит тест. Проверяются:
- варианты ответа — один элемент с ролью «переключатель»/«флажок» и состоянием, выбор работает;
- поле сопоставления называет подсказку («Соответствие для «Лекция»»), роль «выпадающий список»;
- текст вопроса и заголовок экрана — заголовки; кнопки «Назад» и «Прочитать вслух» подписаны;
- экран теста проходит ATF в светлой, тёмной, обеих контрастных темах и с «Очень крупным» текстом;
- настройки отображения: роли и работа переключателей;
- «Нет подключения к интернету» в ошибке и плашке — live region;
- контрольный тест: заведомо плохая кнопка (20 dp без подписи) обязана провалить ATF — проверки действительно включены.

Последний прогон: эмулятор Pixel 8a (Android 14) и Honor LLY-NX1 (Android 16) — 14/14.

Общий код для iOS проверяется компиляцией прямо на Windows:
```
./gradlew :shared:compileKotlinIosSimulatorArm64
```

## Особенности
- **Кириллица в пути проекта на Windows.**
  - В `gradle.properties` включён `android.overridePathCheck`.
  - Build-каталоги модулей вынесены в `%USERPROFILE%\.student-testing-build` (см. `build.gradle.kts`): иначе тестовая JVM не находит классы.
  - APK после сборки лежит в `%USERPROFILE%\.student-testing-build\androidApp\outputs\apk\debug\`.
- **Черновики тестов.** Ответы сохраняются на устройстве и переживают перезапуск приложения. Если сеть пропала во время отправки, повторная отправка блокируется, пока пользователь не проверит «Результаты».
- **«Запомнить меня».** При входе отправляется `lifetimeKind = 2`: refresh-токен живёт 30 дней.
- **Debug-сборка** ставится рядом с release: `applicationId` с суффиксом `.debug`.
- **Инкрементальная компиляция Kotlin отключена** (`kotlin.incremental=false` в `gradle.properties`): Kotlin 2.4 на этом проекте
  падает при закрытии кешей («Storage … is already registered»), даже на чистом каталоге сборки. Полная пересборка `shared` — около 30 с.
  Когда баг исправят в новой версии Kotlin, строку можно убрать.
