# Сценарии собственных моделей ИИ

Проверяют три функции на своих моделях: проверку свободных ответов, подсказку критериев и скан лекции.
Два уровня:

- `api_check.py` — через API бэкенда, без телефона, ~30 с. Запускать после любых изменений моделей или логики проверки.
- `phone_check.py` — на Android-телефоне через adb: студент набирает ответы и сдаёт тест, преподаватель просит критерии и распознаёт скан. ~5 мин.

Что проверяется:

| Сценарий | Проверки |
|---|---|
| grading | каждый ответ из `cases.json` получает допустимый исход; своя модель сама не ставит балл ниже полного; попытки обмана уходят преподавателю; студент не видит предварительных баллов и комментария ИИ; на телефоне — анимация проверки и автообновление итога |
| criteria | 2–5 критериев, сумма баллов равна баллам вопроса, время ответа |
| scan | скан распознан, в разметке есть заголовки и списки, время |

Исходы ответа в `cases.json` (`allowed`): `auto_full` — ИИ уверенно поставил полный балл сам; `teacher` — ответ ушёл преподавателю; `suspicious` — попытка повлиять на проверку.

## Подготовка (один раз)

Нужен Python с `httpx` (`pip install httpx`), стенд в Docker с готовыми моделями (`local-ai`, Ollama с `st-criteria`).

Тестовый студент создаётся через регистрацию, поэтому на время подготовки откройте её:

```bash
APP_PUBLIC_REGISTRATION_ENABLED=true docker compose up -d backend
```

```bash
python setup.py
```

```bash
docker compose up -d backend
```

`setup.py` создаёт студента `aitester` в группе PI-201 (пароль — в `out/student.json`, папка в git не попадает), вопросы из `cases.json`, тест и лекцию «AI local test». Повторный запуск ничего не дублирует. Сид-студенты не используются — их попытки не тратятся.

## Запуск

```bash
python api_check.py
```

```bash
python phone_check.py
```

Отдельные сценарии: `python api_check.py grading`, `python phone_check.py scan criteria`, число попыток на телефоне — `--attempts 3`. Код выхода 1 — что-то не прошло; подробности — в `out/<сценарий>.json`, скриншот при падении — в `out/`.

Для телефона: устройство в `adb devices`, установлена debug-сборка, приложение смотрит на стенд, клавиатура Gboard в русской раскладке (русский текст набирается тапами по клавишам — adb не умеет вводить кириллицу). Координаты клавиш сняты на экране шириной 1080 px и масштабируются; если набор не совпал с ответом, сценарий сообщит «ответ набран» ✘.

Переменные: `ST_API` (по умолчанию `http://127.0.0.1:8080/api/v1`), `ST_ADMIN_LOGIN`/`ST_ADMIN_PASSWORD`, `ST_TEACHER_LOGIN`/`ST_TEACHER_PASSWORD`, `ST_AI_STUDENT_LOGIN`/`ST_AI_STUDENT_PASSWORD`, `ST_APP_PACKAGE`.
